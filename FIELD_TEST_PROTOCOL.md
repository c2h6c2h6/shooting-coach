# Protocole prudent de validation terrain

## Conditions préalables

- version, appareil et règles de moteur consignés ;
- stand autorisé et règlement connu ;
- instructeur déclaré présent pour les phases réelles ;
- protections auditives et oculaires ;
- droit d’arrêter à tout moment, sans justification ;
- aucune fonctionnalité opérationnelle, aucun dégainé, déplacement ou tir en mouvement.

## Phase 1 — données simulées

1. Sauvegarder les données locales.
2. Activer le mode démonstration.
3. Exécuter A à L dans l’ordre.
4. Comparer chaque sortie avec `MVP_VALIDATION_CHECKLIST.md`.
5. Vérifier faits, hypothèses, test, recommandation, résultat et limites.
6. Exporter les signalements utiles.
7. Réinitialiser la démonstration et confirmer que l’historique réel est intact.

Tout écart de sécurité, mélange de données ou certitude catégorique bloque le
passage à la phase suivante.

## Phase 2 — séance réelle encadrée, sans correction

Avec quelques tireurs et au moins un instructeur :

1. créer une séance réelle et une série de référence de cinq coups ;
2. comparer les impacts, métriques et observations à l’avis de l’instructeur ;
3. enregistrer l’avis humain sans modifier la sortie automatique ;
4. arrêter si l’observation est incompréhensible ou manifestement incorrecte.

## Phase 3 — cycle pédagogique encadré

1. sélectionner une seule hypothèse ;
2. vérifier les prérequis et réaliser le test proposé ;
3. enregistrer honnêtement un résultat, y compris non concluant ;
4. ne suivre le travail proposé que s’il est compris, réalisable et jugé sûr ;
5. réaliser au maximum la série de contrôle prévue ;
6. comparer uniquement l’objectif choisi ;
7. arrêter en cas de dégradation, fatigue, douleur, stress, incident ou doute.

## RETEX

Après chaque cycle, recueillir séparément :

- le retour du tireur ;
- le retour de l’instructeur ;
- l’avis humain sur l’hypothèse ;
- les signalements ;
- le rapport JSON de séance ;
- la ligne de checklist.

Une amélioration isolée n’est jamais une validation de la cause. Une règle
n’est modifiée qu’après revue de plusieurs cas documentés. La décision suivante
porte d’abord sur le moteur, l’interface ou, seulement si le MVP est jugé
pertinent, le lancement de la photographie automatique.
